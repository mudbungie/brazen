Gap from providers.md §9 CR-CC item (4), 2026-09-28. A model-returned image on Google/Cloud Code arrives as one part carrying inlineData AND a very large thoughtSignature (~900 KB observed on gemini-3.1-flash-image via antigravity). The decoder emits ContentKind::Image + ImageDelta and IGNORES the signature, so a harness cannot replay the generated image as an assistant turn for multi-turn image editing; Gemini likely requires the signature on replay (as it does for functionCall thoughtSignature, bl-61a9). Today's workaround: re-send the file as user input (-f bz-<hash>.jpg). Design question first: carry the signature on the image block (Delta::SignatureDelta onto a new Content::Image signature slot, mirroring ToolUse.signature) and encode Image in a model turn as inlineData+thoughtSignature on Google; decide what other dialects do with it (drop, like Thinking). Needs a live probe: does an assistant-turn image replay without the signature 400?
