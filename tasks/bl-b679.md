## Problem

There is no way to see which providers `bz` can route to. `--list-models` answers
"what models does provider X serve?"; nothing answers "what is X, and which X's
exist?".

`--dump-config` is the closest surface and is deliberately the WRONG one. config.md
§6 (bl-d67a): "the defaults operand is **omitted** from the dump ... It never shows
`anthropic`, `openai`, `claude-code`, ... The effective table is the dump's rows
*merged over* `data/defaults.toml`". So the 7 built-in rows are invisible; a user
sees only their own. That section closes with: "The read is `bz --provider <name>`
(resolution, which sees the floor), **never the dump**" — i.e. today the only read
of the effective table is to *route to one row and see if it works*. There is no
listing.

## Deliverable

`bz --list-providers` — a control short-circuit flag, the local sibling of
`--list-models`, per arch §5.10.1 ("A new control operation is a new flag").

- **ZERO round-trips.** Purely local: the merged config (WITH the defaults operand,
  the one difference from `--dump-config`) plus a credential-store/ambient read.
- **Rows in `providers` order** — the same list `route()` reads forward, so the
  listing IS the routing priority and the head is the zero-config default. Order
  carries that fact; no `default` marker is stored or printed (don't store what you
  can compute).
- **Four facts per row**: `name`, `protocol`, `auth`, `credential`.
- **`credential` is `resolved_secret`'s answer minus the network** — the same
  precedence, so the column can never disagree with what a run would do:
  `not required` (auth=none) / `inline` (--api-key or BRAZEN_API_KEY, which is
  provider-agnostic and shadows any row) / `stored` / `ambient` / `missing`.
- **Output = the resolved `OutMode`**, exactly as `--list-models` folds it
  (`--json` / `BRAZEN_OUTPUT=ndjson` / file `output=`): Ndjson emits
  `{"providers":[{name,protocol,auth,credential},...]}`; anything else is the
  padded text table, one row per line.
- Exit 0. `--help`/`--skill`/`--version` short-circuit first (the same probe rule).
  A malformed config file / bad env scalar is the existing 78.
