## Symptom
`bz --list-models --provider openai-chatgpt` returns six ids and omits four the same account can run (the gpt-6.1 pair and two gpt-6 ids). A generation naming one of the omitted ids verbatim succeeds, so the account is entitled; only the listing is short.

## Cause
The built-in row pins `[provider.models] query = [["client_version", "0.0.0"]]`, on the documented premise that a value below every real release is treated as ungated and can never be gated to a subset. That premise no longer holds: the backend gates each model on a MINIMUM client version. Probed with the same credential:

- `0.0.0` -> 6 ids
- a current real 0.x client version -> the same 6
- `1.0.0` and `99.0.0` -> 10 ids (the 6 plus the 4 missing)

## Fix
Pin `99.0.0` — above every real release, so every minimum-version gate passes. Amend the rationale in specs/auth.md, specs/model-discovery.md and README.md, which assert the opposite.

## What this does not fix
`[provider.models]` is a whole-block override: an operator config that carries its own copy of the row keeps its own pin and must be edited by hand.
