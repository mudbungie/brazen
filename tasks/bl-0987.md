Investigation opened 2026-09-21 from the operator's prompt: add image support. FINDING: image/PDF INPUT already ships (Content::Image/Document, -f by extension, every dialect maps or rejects loudly). The gap is OUTPUT: Google inlineData parts and OpenAI Responses image_generation_call items are silently DROPPED by the decoders today (Google blocks.rs has no inlineData arm; Responses item_added returns vec![] on unknown item types). Anthropic/Ollama return no images. Design deliverable: a spec section (canonical-protocol.md: ContentKind::Image at block open with media_type, base64 delta grain; providers.md per-dialect decode; interactive-output.md / architecture §5 text-mode contract for a binary block: --json carries base64 inline; --text writes a file and prints its path on stderr, or --out <path>).
