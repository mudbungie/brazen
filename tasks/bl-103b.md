The first real pasted-code sign-in (auth 7.7) ended in a serde type error: the token endpoint answered an error body whose `error` is an object, the parser reads only the RFC 6749 string, and the vendor's reason was discarded.

1. parse_token_response reads `error` as a string or as an object (`type`/`message`), keeps `error_description`, and a non-success body it cannot read is quoted, bounded, with the HTTP status. A body carrying a token is never quoted. Poll signals keep working in either shape.
2. Row data: `token_style` (default rfc6749 = today's bytes; json = a JSON object body carrying the same pairs, plus `state` on the authorization-code grant). No vendor compiled in.
3. Spec first: auth 7.1, 7.5, 7.7; README row reference.
