Canonical `Usage` maps each provider's own counters unaltered, and the
providers disagree about whether the cached slice sits **inside** the
prompt counter or **beside** it. Nothing on the event, and nothing in
`specs/architecture.md` §3.2, says which shape a given `Usage` is — so a
consumer that wants "tokens this call consumed" cannot compute it without
knowing the protocol, which is exactly the fact brazen exists to hide.

The decode sites, all five:

| protocol | prompt counter | cache_read source | overlap |
|---|---|---|---|
| `anthropic` | `input_tokens` | `cache_read_input_tokens` (+ `cache_creation_input_tokens` → cache_write) | **disjoint** |
| `openai` | `prompt_tokens` | `prompt_tokens_details.cached_tokens` | **contained** |
| `openai_responses` | `input_tokens` | `input_tokens_details.cached_tokens` | **contained** |
| `google_genai` | `promptTokenCount` | `cachedContentTokenCount` | **contained** |
| `ollama_chat` | `prompt_eval_count` | — (both `None`) | n/a |

So `input + output + cache_read + cache_write` — the obvious total, and
the one §3.2 neither blesses nor forbids — is right on Anthropic and
bills the cached slice **twice** on the other three, with the inflation
growing with the cache hit rate. It is worst exactly where a long
conversation is cheapest.

Not hypothetical. A downstream harness derives its whole-tree token
budget that way. One step's canonical usage line, from an OpenAI-shaped
row:

    {"type":"usage","input_tokens":93556,"output_tokens":132,
     "cache_read_tokens":91648,"cache_write_tokens":null}

93,556 tokens of prompt billed as 185,336. Over one agent tree: 2,248,984
derived against 1,796,888 overlap-corrected, +25% phantom — enough to
trip a declared 2,000,000-token ceiling and end a conversation one model
call from its answer.

**Two shapes, and the choice is a contract decision, not a bug fix.**

1. **Normalize in the decoders.** Each OpenAI-shaped/Google decoder
   subtracts the cached count out of the prompt counter, so the four
   canonical fields are **disjoint slices by contract** on every
   protocol and their sum is the call's real token consumption
   everywhere. One change, every consumer fixed, and the canonical
   surface finally means one thing. The cost is real: today a counter is
   the provider's own number and can be checked against a provider's own
   dashboard; after this it is brazen's derived number, so a normalized
   `input_tokens` no longer matches `prompt_tokens` on the wire. Under
   `v=1` this is a **semantic change to an existing value** (§3.2's own
   bump rule), which is the strongest argument against doing it
   silently and the strongest argument for doing it before 0.1.0 freezes
   the vocabulary.

2. **Document the overlap and leave the numbers alone.** §3.2 states
   per-protocol whether the cached slice is contained, and the `Usage`
   doc comment says so too. No behavior change, no `v` question — but
   every consumer then needs the protocol name to add four numbers up,
   and the protocol is not on the event, so this shape is only complete
   if brazen also **surfaces which shape applies** (a canonical field on
   the usage event, or the protocol on `MessageStart`).

A third option — a derived `total_tokens` on `Usage`, computed by the
decoder that knows the overlap — is additive under `v=1`, needs no
protocol on the wire, and leaves every existing counter byte-identical
to the provider's. It costs one field and answers the only question
consumers actually ask.

Whatever lands, a fixture per protocol shape should pin the rule, and the
`--json` NDJSON contract (§5.2) needs the same statement.

**Downstream state.** The consuming harness has landed a defensive fold
— `max(input, cache_read + cache_write) + output`, exact under
containment, a floor under disjointness, degrading to `input + output`
when no cache counter is reported (its ball: lernie bl-68f5). That fold
exists **only** because brazen does not answer the question; it collapses
back to a plain sum the day option 1 lands, or reads the declared shape
the day option 2 or 3 does. It is a workaround holding a place, not a
settlement.
