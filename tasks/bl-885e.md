Gap from providers.md §9 CR-CC item (2), 2026-09-28. The antigravity row (google_cloudcode) declines --list-models (models_shape None) because the backend's listing is POST {base}/v1internal:fetchAvailableModels (GET → 404) returning a name-KEYED MAP {models:{"<id>":{displayName,quotaInfo,model,apiProvider,…}}}, not the GET + array the one generic decode_models reads (model-discovery.md §3). 33 ids seen incl. gemini-2.5-flash/pro, gemini-3.1-flash-image, gemini-3.x-flash-* tiers, claude-sonnet-4-6, claude-opus-4-6-thinking, gpt-oss-120b-medium. Consequence: no cache, so partial -m matching and the no-model default can't work on that row. Design: ModelsShape gains method (WireRequest.method already exists) and a map-keyed shape (ids = object keys) as DATA — or a row [provider.models] override — without a per-protocol decode_models. quotaInfo.remainingFraction may be worth surfacing.
