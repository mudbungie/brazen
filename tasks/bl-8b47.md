Evidence: the lernie-usability round-2 comparator drove one litany agent through four steps on two provider rows. claude-sonnet-4-6 via claude-session-direct: cache_read 0 / 11342 / 12666 / 13372. gpt-5.5 via openai-chatgpt (Responses, store:false): cache_read 0 / 3584 / 0 / 0. litany's assembly was byte-identical and append-only on both rows (litany bl-b902 measures it in src/prompt/tests/prefix_ladder.rs). The Anthropic encoder places cache_control automatically (src/protocol/anthropic/encode/cache.rs: last system block + rolling mark + one lookback mark) and the claude bill shows it working. The OpenAI Chat and Responses encoders send no prompt_cache_key (repo-wide grep: zero hits) and no previous_response_id (specs/providers.md: brazen is stateless). OpenAI's automatic prefix cache routes by prompt_cache_key; without it a growing, stateless, fully-resent input lands on whichever replica takes it, which is the shape of the 0s. Ask: one canonical field — CanonicalRequest.cache_key: Option<String> — projected to prompt_cache_key by the openai-chat and openai_responses encoders and ignored by the Anthropic encoder (whose placement stays policy, specs/anthropic-messages.md §2.10). Nothing else changes; a None keeps today's wire byte for byte. litany's half (filed as the litany side of bl-b902) is to hand the agent id — one per branch, stable for the branch's life — through that field from src/prompt/dispatch/canonical.rs::build_request once the version that carries it is pinned.
