## Ops performed (not repo state; recorded so it is reproducible)

- `~/.config/brazen/config.toml`: `name = "codex"` -> `name = "openai-chatgpt"`.
  `base_url` unchanged — `https://chatgpt.com/backend-api/codex` is the BACKEND
  path and has nothing to do with the row name.
- `~/.local/share/brazen/credentials/codex.json` -> `openai-chatgpt.json`.
  Cred files are keyed on row name; renaming one without the other just re-creates
  the same SKIP under a new name.

Verified: `bz --list-providers` -> `openai-chatgpt  openai_responses  oauth2  stored`,
and `BRAZEN_LIVE=1 BRAZEN_LIVE_FUZZ_SPEND=1 cargo test --test live_fuzz_openai --
--ignored` now RUNS all 8 cases where it previously SKIPped every one.

## The SKIP-diagnosability half needed no code

The ball asked that "the SKIP should name the looked-for row". It already does:
- `tests/live_fuzz_openai.rs:154` — "skipping OpenAI ChatGPT-SSO fuzz: no stored
  `{PROVIDER}` cred — `bz --login --provider {PROVIDER}` first"
- `tests/live_support/mod.rs:285` — "== {provider} ==  SKIP ({reason})"
The original mismatch was diagnosable at a glance; it was simply never read.
