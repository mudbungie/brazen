Operator ruling (2026-08-01, codex-comparison follow-up), verbatim: "yes, this is a feature in brazen. possible worth it at some point, definitely not now. not the blocker today, and from the higher order perspective, it should be transparent upgrade when I do implement it."

Filed to record the layer ruling and the constraint, at low priority.

## What (when its day comes)
Today every model call is one bz process = fresh TCP+TLS handshake (~100-300ms). Codex's per-step levers (cached WebSocket sessions, incremental request payloads — codex-rs/core/src/client.rs in openai/codex) all hang off process residency, which the suite refuses. The brazen-shaped subset: TLS session resumption (session tickets persisted in brazen's own cache territory), connection reuse across the retries/attempts *within* one invocation, HTTP/2 where providers support it.

## The binding constraint
Transparent upgrade: no interface change, no resident process, no new state class visible to any consumer — lernie and yog must not know it happened. Anything that violates that is out of scope by ruling.
