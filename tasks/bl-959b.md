Found while closing bl-3dc4 (2026-07-30). specs/release.md §4 rules that a live
assertion is deterministic (blocking) unless the suite declares the case
model-discretion, and places that declaration "per case, in code". But no
machine-readable declaration exists anywhere in `tests/` — the only discretion case
(`reasoning-summary` in `tests/live_fuzz_openai.rs`) is declared in a prose comment.

Consequence: `scripts/release-check.sh` cannot auto-apply §4's bounded retry (up to 3
re-runs) to discretion cases without inventing a second, drift-prone classification
list outside the case. Today the gate reports the failure, prints the re-run command
and the signoff rule, and the bounded retry stays a human action.

Work: add the marker in the suite itself (e.g. a field on the case tuple/struct next
to `Shape`), so the declaration rides the case per §4; then let release-check (or the
harness) apply the retry policy mechanically. No new env spellings.

Scope: `tests/live_fuzz_openai.rs` + `tests/live_support/openai.rs` (the case
registry), possibly `scripts/release-check.sh` classification. Related: bl-3dc4
(where found), specs/release.md §4.
