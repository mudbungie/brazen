Operator ruling (2026-08-01, codex-comparison follow-up), verbatim: "window awareness is a feature request, good... We should get it from brazen, and carry it forward."

## What
A model row's context window size becomes a brazen-owned fact, readable by consumers: carried on the list-models / dump-config surface (wherever the row's capability facts live — verify the actual shape before choosing). Downstream: lernie/yog derive context-fullness (yog ball filed for the status-bar rendering) by dividing real per-step input-token Usage by this window.

## Layer-law note, recorded deliberately
The layer table says brazen never owns "model catalogs beyond routing"; lernie's models.yaml (which today carries context windows) is being extracted per lernie bl-35e2. The operator ruling above places window size with brazen — a capability fact of the wire's model row, like token counters, not policy. If implementation finds this fighting brazen's own docs, amend the doc per the ruling, don't code around it.

## Constraints
- A fact, not an estimate: provider-reported where the API offers it, config-declared on the row otherwise.
- No pricing, no policy — the counter/capability boundary stays.
